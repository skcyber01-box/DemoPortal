# OneSpace Demo Portal

หน้าเว็บกลางสำหรับ Demo โครงการของ OneSpace ในห้องประชุม รายการโครงการอยู่ด้านซ้าย เลือกแล้ว Demo เปิดในหน้าเดียวกันด้านขวา

- ผู้ชมต้อง **เข้าสู่ระบบด้วยอีเมล + รหัส 6 หลัก** ที่ส่งทางอีเมล
- **Super Admin** เพิ่ม/ลบผู้ชม และกำหนดว่าแต่ละอีเมลดู Demo ใดได้บ้าง ที่หน้า **ตั้งค่า**
- ผู้ชมแต่ละคนได้รับรายการโครงการเฉพาะที่มีสิทธิ์จากเซิร์ฟเวอร์ ไม่เห็นแม้แต่ชื่อของ Demo อื่น

## โครงสร้างไฟล์

```
onespace-demo-portal/
├── index.html              หน้าพอร์ทัล
├── login.html              หน้าเข้าสู่ระบบ
├── admin.html              หน้าตั้งค่าสิทธิ์ (Super Admin เท่านั้น)
├── assets/                 หน้าตาและการทำงานฝั่งเบราว์เซอร์
├── middleware.js           ด่านตรวจ: ทุกหน้าต้อง login, หน้าตั้งค่าเฉพาะ Super Admin
├── api/
│   ├── _lib/projects.js    รายการโครงการ ← แก้ไฟล์นี้เมื่อต้องการเพิ่ม/แก้โครงการ
│   ├── _lib/               โค้ดใช้ร่วม (login, สิทธิ์, อีเมล, ฐานข้อมูล)
│   ├── auth/               ขอรหัส · ตรวจรหัส · ข้อมูลผู้ใช้ · ออกจากระบบ
│   ├── projects.js         ส่งรายการโครงการตามสิทธิ์ของแต่ละคน
│   └── admin/              API ของหน้าตั้งค่า
├── package.json
└── vercel.json
```

## สิทธิ์ 3 ระดับ

| ใคร | กำหนดที่ไหน | เห็นอะไร |
|---|---|---|
| **Super Admin** | Environment Variable `SUPER_ADMINS` ใน Vercel | ทุกโครงการ (รวมที่ปิดอยู่) + หน้าตั้งค่า ลบออกจากหน้าเว็บไม่ได้ |
| **ผู้ชมรายคน** | หน้าตั้งค่า → เพิ่มอีเมล | เฉพาะ Demo ที่เปิดสวิตช์ให้ |
| **ผู้ชมทั้งโดเมน** | หน้าตั้งค่า → เพิ่ม `@โดเมน` เช่น `@onespace.co.th` | ทุกอีเมลในโดเมนนั้นได้สิทธิ์ตามแถวนี้ (ถ้ามีแถวรายคนของอีเมลนั้นด้วย ใช้แถวรายคน) |

โดเมนอีเมลสาธารณะ (gmail.com, hotmail.com, outlook.com ฯลฯ) เพิ่มทั้งโดเมนไม่ได้ ต้องเพิ่มรายคน

## หน้าตั้งค่า (สำหรับ Super Admin)

เข้าที่ลิงก์ **ตั้งค่า** มุมขวาบนของพอร์ทัล หรือ `/admin.html`

- **เพิ่มผู้ชม** — ใส่อีเมลหรือ `@โดเมน` ชื่อ/หน่วยงาน และเลือก Demo ที่ให้ดู
- **ตารางผู้มีสิทธิ์** — สวิตช์มีผลทันที
  - **ใช้งาน**: ปิดเพื่อระงับชั่วคราว ผู้ชมที่ login ค้างอยู่จะถูกพาออกเมื่อโหลดหน้าครั้งถัดไป
  - **ทุกโครงการ**: เห็นทุก Demo รวมถึงที่จะเพิ่มในอนาคต
  - **สวิตช์รายโครงการ**: เปิด/ปิดสิทธิ์ทีละ Demo
  - **ลบ**: เอาออกจากรายชื่อ
  - แสดงเวลาที่แต่ละคนเข้าสู่ระบบล่าสุด
- **การแสดงผลโครงการ** — ปิดโครงการเพื่อซ่อนจากผู้ชมทุกคนชั่วคราว (เช่น ระหว่างแก้ Demo) Super Admin ยังเห็นเสมอ

ทุกการเปลี่ยนแปลงบันทึกใน Vercel → Project → **Logs** (ค้นคำว่า `[admin]`) ส่วนการเข้าสู่ระบบค้นคำว่า `[auth] login`

## ติดตั้งบน Vercel (ทำครั้งเดียว)

### 1) ขึ้น GitHub แล้ว Import เข้า Vercel

```bash
cd onespace-demo-portal
git init && git add . && git commit -m "OneSpace Demo Portal"
git branch -M main
git remote add origin https://github.com/<ชื่อบัญชี>/onespace-demo-portal.git
git push -u origin main
```

vercel.com → **Add New… → Project** → เลือก repo → Framework Preset: **Other** → **Deploy**
(deploy แรกจะเข้าไม่ได้จนกว่าจะตั้งค่าข้อ 2–4 ครบ ระบบปิดไว้ก่อนเสมอ)

### 2) บริการส่งอีเมล: Resend

1. สมัคร resend.com (ฟรี 3,000 ฉบับ/เดือน)
2. **Domains → Add Domain** ใส่โดเมนบริษัท เช่น `onespace.co.th` แล้วเพิ่ม DNS record ตามที่ Resend แจ้ง (ทีม IT ที่ดูแล DNS)
3. **API Keys → Create API Key** (Sending access) แล้วคัดลอกเก็บไว้

> ก่อนยืนยันโดเมนเสร็จ ทดสอบได้โดยไม่ต้องตั้ง `MAIL_FROM` แต่จะส่งได้เฉพาะอีเมลที่ใช้สมัคร Resend
> แนะนำให้สมัคร Resend ด้วยอีเมล Super Admin เพื่อให้ login ครั้งแรกได้ทันที

### 3) ฐานข้อมูลสิทธิ์: Upstash Redis (ฟรี) — จำเป็น

Vercel → Project → **Storage** → **Upstash for Redis** (Marketplace) → Create → เชื่อมกับโปรเจกต์นี้
Vercel จะเพิ่ม `KV_REST_API_URL` และ `KV_REST_API_TOKEN` ให้เอง

ใช้เก็บรายชื่อผู้ชม สิทธิ์รายโครงการ เวลาเข้าสู่ระบบล่าสุด และตัวนับป้องกันการเดารหัส
(ถ้ายังไม่ได้เชื่อม จะ login ได้เฉพาะ Super Admin และหน้าตั้งค่าจะแจ้งเตือน)

### 4) Environment Variables

Vercel → Project → **Settings → Environment Variables** (Environment: Production และ Preview)

| ชื่อ | ค่า | จำเป็น |
|---|---|---|
| `SUPER_ADMINS` | อีเมล Super Admin คั่นด้วยจุลภาค เช่น `skcyber01@gmail.com` | ✔ |
| `AUTH_SECRET` | ข้อความสุ่มยาวอย่างน้อย 32 ตัวอักษร ใช้เซ็น cookie ห้ามเปิดเผย สร้างได้ด้วย `openssl rand -base64 48` | ✔ |
| `RESEND_API_KEY` | API key จากข้อ 2 | ✔ |
| `MAIL_FROM` | ผู้ส่ง เช่น `OneSpace Demo Portal <demo@onespace.co.th>` (โดเมนต้องยืนยันใน Resend แล้ว) | ✔ หลังยืนยันโดเมน |
| `SESSION_DAYS` | จำนวนวันที่ login ค้างไว้ (ค่าเริ่มต้น 7) | ไม่บังคับ |

กด **Redeploy** หลังเพิ่ม/แก้ตัวแปรทุกครั้ง

### 5) ใช้ชื่อโดเมนบริษัท (ไม่บังคับ)

Vercel → Project → **Settings → Domains** → เพิ่ม เช่น `demo.onespace.co.th` แล้วตั้งค่า DNS ตามที่ Vercel แจ้ง

## เพิ่ม/แก้โครงการ

แก้ `api/_lib/projects.js` แล้ว push โครงการใหม่จะปรากฏในหน้าตั้งค่าให้เปิดสิทธิ์ได้ทันที
(ผู้ชมที่ตั้ง **ทุกโครงการ** ไว้จะเห็นโครงการใหม่อัตโนมัติ ผู้ชมอื่นต้องเปิดสวิตช์ให้)

```js
{
  id: 'kpi-region6',                 // ใช้อ้างอิงสิทธิ์ ตั้งแล้วอย่าเปลี่ยน
  name: 'KPI Monitor เขตสุขภาพที่ 6',
  group: 'region',                   // ต้องตรงกับ id ใน GROUPS
  status: 'demo',                    // live | demo | proto | soon
  summary: 'คำอธิบาย 1–2 ประโยค',
  owner: 'หน่วยงาน',
  tags: ['คำค้น'],
  url: 'https://...',
  embed: true,                       // true = เปิดในพอร์ทัล, false = เปิดแท็บใหม่
  deck: 'https://...'                // (ไม่บังคับ) ลิงก์สไลด์
}
```

## ข้อจำกัดที่ควรรู้

สิทธิ์นี้ควบคุม **สิ่งที่แต่ละคนเห็นในพอร์ทัล** แต่ Demo ที่อยู่คนละ Vercel project
(เช่น `doctor-assist-blush.vercel.app`) ยังเปิดได้ถ้ามีคนรู้ลิงก์ตรง
ถ้าต้องการให้ Demo อยู่หลังด่าน login และสิทธิ์เดียวกันจริงๆ ต้องย้ายไฟล์ Demo มาไว้ใน repo นี้

ถ้าต้องการตัดทุกคนออกจากระบบทันที ให้เปลี่ยน `AUTH_SECRET` แล้ว Redeploy ทุกคนจะต้อง login ใหม่

## ใช้งานในห้องประชุม

| ปุ่ม/คีย์ | ทำอะไร |
|---|---|
| `/` | ไปที่ช่องค้นหา |
| `P` หรือปุ่ม **โหมดนำเสนอ** | ซ่อนรายการ ให้ Demo เต็มหน้าจอ |
| `]` / `[` | ไปโครงการถัดไป / ก่อนหน้า |
| `Esc` | ออกจากโหมดนำเสนอ |
| ปุ่ม **คัดลอกลิงก์** | ได้ลิงก์ตรงไปยังโครงการนั้น (ผู้รับต้อง login และมีสิทธิ์) |
